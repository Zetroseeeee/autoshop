# Basket

Personal multi-store shopping basket. Paste product links from any store; the app scrapes name, brand, price and photo server-side, can re-shoot every item as a uniform AI **studio packshot** on white, groups everything by store with GBP totals, and walks you through a store-by-store **checkout run** (open the store, buy there, mark ordered, next). Installs as a PWA; on iPhone an **Add to Basket** Shortcut sits in the share sheet.

**Hard rule:** no payments, card details or checkout ever happen inside this app. Checkout means opening the store's own site.

## Stack

Next.js 16 (App Router, TypeScript strict, Tailwind v4) · Postgres on Neon via drizzle-orm/drizzle-kit · Vercel Blob · Google Gemini (`@google/genai`) · cheerio + playwright-core + `@sparticuz/chromium` · optional ScraperAPI · Vercel (free tier).

## What changed from the brief (things that had moved on)

| Brief said | Current reality (Aug 2026) | What the app does |
| --- | --- | --- |
| `middleware.ts` | Next 16 deprecated `middleware` → **`proxy.ts`** (Node runtime) | `proxy.ts` is the passcode gate |
| Gemini `gemini-2.5-flash-image` | Now legacy; **`gemini-3.1-flash-image`** is the recommended Nano Banana model | Tries `gemini-3.1-flash-image`, falls back to `gemini-2.5-flash-image` (`lib/gemini.ts`) |
| Text fallback model unspecified | Cheapest stable text model is **`gemini-3.5-flash-lite`** | Used for the brand/category-only fallback |
| "give this function 1536 MB memory" via `vercel.json` | Vercel no longer allows memory in `vercel.json` (build warning) and **Hobby functions always get 2 GB** | No memory config; Tier 2 routes set `maxDuration = 60` instead |
| `HARD_SITES` = vinted, depop, grailed, ebay | Zara (Akamai interstitial) and H&M (Akamai 403) also block both plain fetch *and* headless Chrome | `zara.com`, `hm.com`, `stockx.com`, `goat.com` added |

One addition to the Tier 1 parser worth knowing about: after JSON-LD → meta → `itemprop` → `<title>`, it reads **embedded JSON state** for a few known shapes (ASOS `"current":{"value":…}`, Uniqlo `"prices":{"base":…}`, generic `"price":"12.34"…"priceCurrency":"GBP"`). That is what makes ASOS and Uniqlo fill without Chrome. It never invents values — the shapes are exact and sanity-checked.

## Local development

Prerequisites: Node 20+, a Postgres you can reach (local or a Neon dev branch), and optionally Google Chrome (auto-detected for Tier 2 rendering on macOS/Linux).

```bash
cp .env.example .env.local   # fill in DATABASE_URL and ACCESS_CODE at minimum
npm install
npm run db:migrate           # applies drizzle/ migrations
npm run dev                  # http://localhost:3000
npm test                     # parser fixture tests (vitest)
npm run build                # production build
```

Scripts: `dev`, `build`, `start`, `lint`, `typecheck`, `test`, `db:generate` (new migration from `lib/schema.ts`), `db:migrate`, `db:push`, `db:studio`. Icons are generated by `node scripts/icons.mjs`.

## Environment variables

See [`.env.example`](.env.example) — every key is documented there. Required: `DATABASE_URL`, `ACCESS_CODE`, `APP_URL`. For studio photos: `GEMINI_API_KEY` + `BLOB_READ_WRITE_TOKEN`. Optional: `SCRAPER_API_KEY`, `AUTO_STUDIO`, `STUDIO_MONTHLY_CAP`, `BACK_VIEW`, `CRON_SECRET`, `CHROME_EXECUTABLE_PATH` (local only).

`/settings` shows which keys are present (booleans only).

## Deploying to Vercel

1. Push this repo to GitHub and import it in Vercel (framework: Next.js). `vercel.json` sets the build command to `npm run db:migrate && npm run build`, so migrations run on every deploy.
2. **Database:** create a Neon project (or use Vercel's Neon integration). Set `DATABASE_URL` to the **pooled** connection string (`…-pooler.…neon.tech/…?sslmode=require`).
3. **Blob:** Storage → Create → Blob. Vercel adds `BLOB_READ_WRITE_TOKEN` automatically.
4. **Gemini:** create a key in Google AI Studio → `GEMINI_API_KEY`.
5. Set `ACCESS_CODE` (digits — the unlock screen is a numeric keypad), `APP_URL` (e.g. `https://basket-emile.vercel.app`), and any optional keys.
6. Deploy. Open the URL → passcode screen → unlock. Add to Home Screen on iOS; "Install app" on Android/desktop Chrome.

Tier 2 (rendered fetch) uses `@sparticuz/chromium` on Vercel automatically; it needs no config. If you ever see Chromium download/extract errors in function logs, the route still degrades to the Tier 1 result — nothing breaks.

## Adding items

- **Paste bar** on `/` (pasting a link adds it immediately; several links at once work too).
- **`/api/quick-add?code=<ACCESS_CODE>&url=<link>`** (GET or POST; JSON when `Accept: application/json`, otherwise 302 → `/`). Lightly rate-limited; 401 on a bad code.
- **Share sheet on Android / desktop Chrome:** the PWA manifest declares a `share_target` → `/share` → quick-add.
- **iPhone:** iOS Safari has no share-target support, so build the Shortcut below once.

### iOS Shortcut — "Add to Basket"

1. Open **Shortcuts**, tap **+**.
2. Tap the name at the top → **Rename** → `Add to Basket`.
3. Tap **ⓘ** → turn on **Show in Share Sheet** → **Share Sheet Types**: keep **URLs** and **Safari web pages**. Done.
4. Add action **Get URLs from Input**; input = **Shortcut Input**.
5. Add action **Text** with (replace `YOUR-CODE` with your passcode, and keep `APP_URL` as your deployment):
   ```
   https://APP_URL/api/quick-add?code=YOUR-CODE&url=
   ```
   then insert the **URLs** variable at the end so the link is appended.
6. Add action **Get Contents of URL**: URL = the **Text** variable; Show More → Method **GET**; Headers: `Accept` = `application/json`.
7. (Optional) add **Show Notification** — "Added to Basket".
8. Share any product page → **Add to Basket**. It appears in the basket within seconds.

Prefer to land in the app? Use **Open URLs** instead of *Get Contents of URL* in step 6 — the app adds the item and opens the basket (302).

The same steps are shown on `/settings` with your real `APP_URL` filled in.

## How scraping works (`lib/enrich.ts`)

`POST /api/items {url}` → normalise (https, strip `utm_*`/`fbclid`/…) → insert `pending` → respond → enrich in the background (`after()`), UI polls until done.

1. **Tier 1** — direct fetch (mobile Safari UA, `en-GB`, 8 s) → `lib/parse.ts`: JSON-LD (`@graph`, arrays, `AggregateOffer`/`lowPrice`, `priceSpecification`) → og/twitter/product meta → `[itemprop=price]` → `<title>` with site suffix stripped → embedded JSON price → visible price element. Sanity: `0 < price < £100,000`, relative images absolutised, svg/logo/sprite/favicon rejected, entities decoded, bot-wall pages yield nothing.
2. **Tier 2** — playwright-core render (`domcontentloaded` + 2 s), only when price or image is still missing *and* the host is in `JS_SITES` or the page looked like an app shell. Degrades silently.
3. **Tier 3** — ScraperAPI with JS rendering, only with `SCRAPER_API_KEY` and a `HARD_SITES` host.
4. **Tier 4** — Gemini text, brand + category only. Never a price or an image.

Result → `fetchState`: `ok` (name+price+image) / `partial` / `failed` ("Fetch failed — fill manually", editor opens). Maintain the host lists at the top of `lib/enrich.ts`.

## Studio packshots (`lib/studio.ts`)

"Studio photo" on an item, "Generate all missing" on the basket, or automatically after fetch with `AUTO_STUDIO=true`. Checks the monthly cap (`studio_usage` vs `STUDIO_MONTHLY_CAP`, default 200) → downloads the source image (normalised to a ≤1280 px JPEG with sharp) → Gemini image model with the packshot prompt (style varies by category) → PNG to Vercel Blob → `studioImageUrl`. With `BACK_VIEW=true` a second, clearly labelled **AI guess** back view is generated. Thumbnails prefer the studio image; the editor has an Original / Studio toggle and Regenerate. Any failure keeps the original and shows a toast.

## Daily price check (stretch)

`vercel.json` schedules `GET /api/cron/price-check` daily at 06:00 UTC. Set `CRON_SECRET` in Vercel (it is sent as `Authorization: Bearer …`). The job re-runs Tier 1 on every `want` item; on a drop it stores `previousPriceMinor` and the row shows a struck-through "was £x" badge.

## Scope guard

No payments or card storage, no accounts, no emails/analytics/dark mode, no admin panel, no tests beyond the parser fixtures.
